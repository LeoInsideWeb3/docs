1 · Overview & Verdict

Perpetuals Trading UI — Full Smoke Test

Smoke-tested every perpetuals-facing surface of the staging client end-to-end. The core trading loop — market open → live position → close → position/trade history — is verified end-to-end on both XRPUSDT-PERP and HYPEUSDT-PERP with real market-maker liquidity and profitable round trips (+0.71 USDT on XRP, +0.09 USDT on HYPE). One intermittent issue observed: the HYPEUSDT-PERP page occasionally fails to load ("Loading trading interface") — it loaded and traded cleanly on retry.

Note on a reported "bug" that turned out to be correct behavior

An initial hypothesis that the order size input "does not sync to React state" was refuted. In quote (USDT) unit mode the field stores the base-converted amount — e.g. typing 100 (USDT) is stored as 1.08 (HYPE). Typing a tiny notional (e.g. 0.01 USDT) converts to 0.000 base units and is silently rejected — see 5.2.

Method Notes

  • DOM is ground truth. Screenshots under CDP automation can lag or show stale frames (e.g. a tab switch that already succeeded still renders the old frame). All assertions below are DOM-based.
  • Input path used: focus + real keyboard events (Input.insertText) for text fields; native setter + value-tracker desync as a fallback; React fiber state read directly to verify the form's stored amount.
  • Network probe caveat: the __netLog probe intercepts window.fetch/XHR but did not capture the actual order-submission POSTs (the app's API client bypasses interception). Order outcomes were therefore verified via the Order History / Position History / Position panel instead of the probe.
  • No real funds at risk: staging environment, internal transfer balances.

What could not be exercised

Conditional trigger execution on HYPE (see 5.1 — the page loaded on retry but no trigger-market scenario was held to maturity) and funding-payment / liquidation (no long-horizon position was held). These remain future test items.

3 · End-to-End Flow (XRP · HYPE)

Verified Round Trips

With real MM quoting (XRP top-of-book ≈ 38,000 XRP; HYPE ≈ 637 HYPE at best ask), the complete user journey — place market order → position opens with live PnL → close via confirmation → realized PnL lands in Position History — was executed and verified on both markets.

Step by Step (XRP)

  1. Market open (Long)Switched the order form to Market · 10x · quote unit; typed 500 USDT. The estimates area computed Position Size 326.88 XRP, Margin Required 49.999 / 49.999 USDT. Clicked Open Long.
  2. Fill & positionA market order filled at 1.5304 → position row appeared: 326.818 XRP · 500.03 USDT · Long · 10x · Cross · margin 50.02 · entry 1.5304, PnL ticking live against mark price.
  3. Close flowSwitched the form to Close mode (Market), typed the full size 326.818 XRP, clicked Close Long. A confirmation card appeared with estimates: est. fill 1.5328, slippage ~0.03%, est. fees −0.200378 USDT. Confirmed.
  4. Position closedThe close market order filled at 1.5326 (slightly above entry — small profit). The position row disappeared; realized PnL is viewable in Position History.

  3. Close flowClose mode (Market), full size 1.08 HYPE, Close Long → confirmation card with est. fill / slippage / fees → confirmed.

5 · Issues & Observations

Findings, Ordered by Impact

One intermittent load failure and two minor UX observations. No money-safety or accounting bug was found in the surfaces exercised.

5.1 Intermittent — HYPEUSDT-PERP page fails to load on first navigation

ItemDetail
SymptomOn one navigation the page stuck on "Loading trading interface"; title never gained the live price prefix
NetworkHTTP layer healthy — all API calls 200 (incl. market-fee-rate?market=HYPEUSDT-PERP). Zero market-data requests issued; no WebSocket connection established (no ws:// resources, no Centrifuge client)
ResolutionOn retry (fresh navigation) the page loaded fully — mark 92.424, order book with real MM depth — and a full round trip (open + close) executed cleanly. Intermittent client streaming-load failure, self-resolving.
Follow-upIf it recurs, capture Centrifuge connect/subscribe logs; check the market-data gateway's channel availability for HYPEUSDT-PERP

5.2 Sub-minimum notional is silently rejected

Typing a notional that converts to 0.000 base units (e.g. 0.01 USDT) and clicking Open/Close produces no order, no toast, no inline error. The estimates area simply shows "—". Low-risk UX gap: users get no feedback on why nothing happened. Recommend a minimum-order-size hint/toast.

5.3 Order History omits zero-fill expired IOC orders

Expired IOC orders with a partial fill appear in Order History; expired IOC orders with zero fill are not listed. Minor observability inconsistency worth confirming as intended.

Method quirks worth knowing

  • Screenshots are stale under CDP automation — always verify state via the DOM (e.g. a tab switch that succeeded still renders the old frame in a screenshot).
  • Form clicks via CDP mouse are unreliable for some controls (leverage slider, Open/Close toggle); the same controls respond to a scripted element.click(). Automation artifact, not a user-facing defect.
  • The size field stores base-converted amounts regardless of display unit — verify via the React fiber state (currentBidOrderFields.amount) rather than the input's DOM value.
  • Order submission is not captured by a window.fetch/XHR probe on this client; use Order/Position history as the source of truth for whether an order was placed.
