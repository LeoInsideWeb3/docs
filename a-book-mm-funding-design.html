A-Book 做市商充值
一条方向的资金闭环

版本 v1.0 · 2026-10-28 · 作者 NeoDAX 团队 · 状态: 评审中

当币安做市账户的可用余额不足或保证金风险升高时，系统自动从专用做市资金钱包向币安充值地址转入 USDT，币安到账后由 MM 程序确认并入合约钱包。全程不需要人工介入，但每一步可审计、可追回、可暂停。

Objective

目标与资金方向

01

只支持一条资金方向：从 Cage 做市资金钱包流出，经币安现货钱包，最终进入 USDⓈ-M 合约钱包。没有反向流出。

ALARM

本方案不做的事：从币安提币、归集多余资金退回、复用用户充值 / 提现 / 客户余额、自动调整币安 API Key 权限。

唯一资金方向
Cage 做市资金钱包（链上 USDT）
    → 币安充值地址（固定地址，Cage 白名单管理）
    → MM 现货钱包（链上到账后由币安记入）
    → MM USDⓈ-M 合约钱包（由 MM 程序发起内部划转）
NOTE

信任分离：币安 API Key 只存 MM 程序。`mm_connector` 不读币安钱包、不保存币安凭据、不调币安私有接口。它只消费 MM 程序签名的账户快照。

Responsibilities

组件职责

02
MC

mm_connector

消费 MM 账户快照 → 评估策略 → 创建充值申请 → 驱动状态机 → 关联 Cage 与 MM 的回执证据 → 发布风险状态。它是本方案的协调者，不直接碰链或币安。

协调者
MM

MM 程序

持有币安凭据，读取合约账户余额和保证金，查询充值历史，执行现货到合约的内部划转，保存币安侧操作证据。多副本时必须共享幂等记录或由选主实例统一执行。

币安唯一入口
CG

Cage

管理专用做市资金钱包，保存固定币安充值地址，校验白名单和限额，签名并广播链上交易，跟踪确认深度，发布转账事件。私钥只存在于签名边界内。

链上唯一入口
PM

下游消费者
AD

管理后台

配置策略、审批大额申请、暂停自动充值、查看状态和执行人工复核。任何人工状态修改记录操作者、时间、原因和证据。

干预入口

Policy

充值策略与金额计算

04

策略的核心是回答一个问题：当前应该补多少？答案取三个维度缺口的最大值，扣除在途金额。

金额公式
// A = 当前可用余额;  M = 当前保证金余额;  MM = 当前维持保证金
// F = 预测资金需求 + 安全缓冲;  P = 在途金额（已发起未到合约钱包）
// T = 目标可用余额;  R = 目标保证金率

available_deficit = max(0, T - A)
ratio_deficit     = max(0, MM / R - M)
forecast_deficit  = max(0, F - A)
gross_amount      = max(available_deficit, ratio_deficit, forecast_deficit)
requested_amount  = max(0, gross_amount - P)

结果经过资产精度、最小金额、单笔上限、日累计上限、Cage 可用余额和 Gas 余额校验。

参数作用
min_available_balance低于此值触发硬性充值判断
target_available_balance充值完成后的目标可用余额
warning_margin_ratio开始预警和普通充值判断
critical_margin_ratio紧急充值并进入至少只减仓状态
target_margin_ratio充值后的目标保证金率
forecast_horizon近期资金需求预测窗口
confirmation_samples普通触发需要的连续异常样本数
max_daily_top_upUTC 自然日累计自动充值上限
cooldown两次已完成充值之间的最短间隔
NOTE

为什么不直接看余额：保证金率是比余额更早的风险指标——余额还没见底，维持保证金占比可能已经到了临界线。三个维度取最大值，能覆盖"余额还够但风险已经升高"的场景。

WARN

防重复充值：每个 venue_account_id + asset 同时只允许一笔活动充值。在途金额 P 必须计入下一次决策——链上确认和币安到账各需要分钟到小时不等，忽略在途就会在同一缺口下连续发射多笔。

Flow

端到端流程（10 步）

05
STEP 1–2 OK

读取快照并评估策略

+

`mm_connector` 定时调用 MM 程序的 `GetTreasuryAccount`，获得带源时间、版本和健康状态的账户快照。策略命中后，在同一数据库事务中写入充值申请和 Outbox 记录（借用 mm_connector 已有的 Inbox/Outbox/Worker Lease 模式）。

快照校验不通过（过期、版本倒退、账户不匹配、金额非法、source_healthy=false、保证金率不一致）→ 拒绝并视为无有效数据。
STEP 3 WARN

金额超限 → 人工审批

+

若金额超过自动额度，状态进入 `APPROVAL_PENDING`，等待管理后台审批。审批期间不做任何链上动作。

STEP 4–5 OK

发命令给 Cage，Cage 校验并预占额度

+

`mm_connector` 发送 `CommandTreasuryTransferRequested`，只传配置好的 `destination_id`。Cage 从白名单读取固定地址、网络和可选 Tag/Memo，校验目标已启用、账户和资产匹配，然后按 `request_id` 原子预占日限额。

新增独立命令 CommandTreasuryTransferRequested，不复用用户提现事件。固定地址如需更换，必须在 Cage 创建新版本、双人复核、小额验证后启用。
STEP 6–7 OK

Cage 广播链上交易并确认

+

Cage 向币安充值地址发送链上交易，持续跟踪确认深度，达到要求后发布 `EventTreasuryTransferConfirmed`。链上确认后，`mm_connector` 调用 MM 程序的 `ObserveTopUp`。

链上交易一旦广播，不允许取消。暂停只停止后续自动动作，已广播交易继续对账。
STEP 8 OK

MM 确认币安入账并划转

+

MM 程序按资产、网络、金额、地址和交易哈希查询币安充值历史，确认现货钱包已入账，然后执行现货到 USDⓈ-M 合约钱包的内部划转，保存币安充值 ID 和内部划转 ID。

相同幂等键返回原操作，不重复划转。多副本时必须共享幂等记录或由选主实例统一执行。
STEP 9–10 OK

最终验证并完成

+

`mm_connector` 获取一份晚于内部划转时间的新账户快照，确认合约账户资金增加、证据完整。满足全部条件后申请进入 `COMPLETED`。

完成条件 = Cage 事件证据 + MM 操作证据 + 新快照资金增加。三缺一 → 不完成。

Failure

故障处理矩阵

07
场景处理风控影响
MM 快照过期 / 读取失败不发起充值至少 REDUCE_ONLY，持续超时后 HALTED
Cage 余额或 Gas 不足申请失败并告警临界风险下保持 HALTED
destination_id 不存在 / 停用 / 资产不匹配终止申请，要求人工核对按缺口严重度决定
Cage 已接受但未广播可安全重试同一请求无
广播返回超时先链上对账，不生成新请求无
链上确认后币安长时间未入账保持原申请并轮询；超时进入人工复核，不再次充值视保证金率
币安已入现货但内部划转失败MM 有界重试临界情况下 A-Book 保持停止加仓
MM 报告完成但新快照未增加进入人工复核不按成功处理
Kafka 事件乱序依据状态版本忽略回退事件无
NOTE

幂等与重试：`request_id` 从创建到完成不变。相同幂等键和 Payload Hash 返回原结果；相同 ID 但不同 Payload 直接拒绝。Cage 广播结果不确定时，先按 Nonce、发送地址和交易记录对账，不能重新发送。重试用有上限的指数退避，超过时限进入 `MANUAL_REVIEW`。

Risk

风控联动

08

充值流程不修改真实保证金指标。只有新的 MM 账户快照才能解除风险状态。

状态含义触发条件
WARNING允许正常交易达到预警线（提前充值中）
REDUCE_ONLY拒绝增加敞口，允许减仓MM 数据不新鲜，或达到临界保证金率
HALTED拒绝 A-Book 新单（按 PM Perp 现有逻辑）Cage 终态失败且缺口仍为临界；或资金已到现货但不能转入合约
NOTE

恢复条件：完成后连续取得配置数量的健康快照，再逐级恢复（HALTED → REDUCE_ONLY → WARNING → 正常）。不能因为一笔充值完成了就直接放开。

Rollout

上线步骤（6 阶段）

09
阶段 1 OK

账户观测（不转账）

+

扩展 MM 账户接口，只记录快照和计算结果。验证数据质量，不做任何资金动作。

阶段 2 OK

影子决策

+

运行策略并生成告警，对照人工判断校准阈值。如果影子期的决策和有经验的运维的判断偏差大，调整阈值再来一轮。

阶段 3 OK

Cage 通道（测试网）

+

部署专用钱包、白名单、额度和独立转账协议，在测试网络验证全链路。

阶段 4 WARN

人工审批（全量）

+

所有生产充值都需审批，验证状态机和对账。这是最长的阶段——用真实操作积累信心。

阶段 5 WARN

受限自动充值

+

仅对小额、单资产、单网络开启自动充值，设置较低日限额。观察失败率和人工复核频率。

阶段 6 OK

扩大额度

+

根据失败率、确认时间和人工复核记录逐步调整。每个阶段保留一键暂停开关。
