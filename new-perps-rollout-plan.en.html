Rollout Runbook for 14 Perpetual Markets

None of these markets has been launched to users yet. They are initialized in PM Perp directly as A_BOOK, executed by MM Connector, with Quote mirroring Binance market data. There is no existing B-book routing, so do not run marketctl book-switch and do not add them to any Finex shard.

Safety boundary

The database row may be status=active so services can discover the market, but the first write must be operational_state=FROZEN. Only after market data, connector, Kafka, risk and account checks pass, switch each market to OPEN through the Admin A-book state API, one at a time.

Four principles

Execution ownershipexecution_book=A_BOOK and desired_execution_book=A_BOOK. Finex must ignore these markets when it receives MarketSync.
Price ownershipMark, order book, trade tape, kline and ticker all come from the matching Binance USD-M symbol. The Binance weight of the A-book mark is 1.0.
Margin modeA-book allows isolated only. Cross-margin orders must be rejected, and the default market setting must resolve to isolated.
One market at a timeValidate while FROZEN, then OPEN a single market; move to the next only after a full observation window.

Do not

Run book-switch; add these markets to any Finex configured_markets; reuse generic risk tiers from older documents; use an OKX/Bybit blended price for A-book liquidation; or open a market without a Binance leverage bracket snapshot.

Must match Binance, but not in public exchangeInfo

max_allowed_leverage, the first-tier maintenance_margin_rate and the full perps_market_risk_tiers must be fetched on release day with a read-only Binance key via the signed GET /fapi/v1/leverageBracket endpoint. Import each bracket verbatim: notionalCap → max_position_qty, initialLeverage → max_leverage, maintMarginRatio → maintenance_margin_rate = maintMarginRatio × 2 (tier 1 stays as-is) — a production safety rule: the A-Book mark is the Binance mark, so doubling the maintenance margin guarantees our liquidation of user positions fires strictly before Binance liquidates the hedge position. initial_margin_rate = 1 / initialLeverage. No snapshot, no release.

Do not present NeoDAX parameters as Binance parameters

maker_fee_rate, taker_fee_rate, depth_level, mm_address, max_net_notional, timeouts and wait windows follow platform policy. max_net_notional must not exceed the Binance first-tier notional cap and is bounded by the connector global limit. Under the platform A-book risk policy, market_order_margin_buffer equals the Binance first-tier maintenance_margin_rate, giving the target of twice the Binance MMR.

The static table is for review only. The actual seed must be generated from, or diffed field by field against, the release-day snapshot; external parameters can change at any time.

Ensure the System House Account Exists

The shared A-book House account must exist in both the PM Perp database and the Raft FSM. Both account_id and app_session_id are fixed to 00000000-0000-0000-0000-000000000009, and owner is the zero address. Do not seed or open any market until this check passes.

4.1 Check the leader startup log

kubectl logs -n <namespace> <leader-pod-name> | grep "\[SYSTEM_ACCOUNTS\]"

Healthy

[SYSTEM_ACCOUNTS] account present in FSM and DB, no action needed
[SYSTEM_ACCOUNTS] all system accounts verified present in FSM

The first line is a Debug log. When production does not enable Debug, seeing only the final all system accounts verified line is also healthy.

Auto-repaired present in DB, missing from FSM

[SYSTEM_ACCOUNTS] account found in DB but missing from FSM, registering into FSM
[SYSTEM_ACCOUNTS] account registered into FSM successfully
[SYSTEM_ACCOUNTS] all system accounts verified present in FSM

Auto-repaired present in FSM, missing from DB

[SYSTEM_ACCOUNTS] account found in FSM but missing from DB, back-filling database record
[SYSTEM_ACCOUNTS] database record back-filled successfully
[SYSTEM_ACCOUNTS] all system accounts verified present in FSM

Failure (startup aborts)

[SYSTEM_ACCOUNTS] CRITICAL: system account missing from FSM after reconciliation

If this line appears, or the final all system accounts verified present in FSM line is missing, stop the release immediately. Do not seed or OPEN.

4.2 Repair system accounts without downtime

Run against the current Raft leader only. It reconciles all required system accounts (including the A-book House) and fills the DB or the FSM in whichever direction is missing. Safe to repeat.

Post-repair gate

Re-run the log check in 4.1 and confirm all system accounts verified present in FSM. If the response is not leader, locate the leader and retry. Any success: false means the repair did not succeed.

PM Perp Seed

Two equivalent carriers per market: the primary path is the Admin API (UpsertPerpetualsMarket) — one atomic call writes the row through the Raft FSM and broadcasts CommandMarketSync. The SQL files below remain the reviewed artifact and the fallback.

The only remaining placeholder

__MM_ADDRESS__ comes from environment config. MMR, max leverage and all risk tiers were filled from the signed Binance /fapi/v1/leverageBracket response of 2026-10-14; notionalCoef is 1 for all 14 markets on this execution account.

Iron rule — never finish with SQL alone (2026-10-27 ARB incident)

Direct SQL bypasses the Raft FSM: the perps_markets row lands, but CommandMarketSync is never published, so every sync-driven component stays unaware the market exists. If SQL is used, you must re-apply the same row through the Admin API and verify "A-Book market sync processed" added=1 in the mm_connector log before moving on.

Rollback and Incident Handling

On failure, freeze first and preserve evidence, then repair along the A-book path. Rollback never changes execution ownership.

  1. FROZEN immediatelyUse the same A-book state API to set the market to FROZEN. Do not book-switch to B-book.
  2. Preserve evidenceRecord the operation id, route version, connector offsets, orders and fills, external account snapshot, reconciliation diff, market data sequence and alert timeline.
  3. Handle exposureWhile user / House / external positions exist, stay FROZEN and repair through the A-book cancel-all / reconcile / reconcile-order paths. Never delete the market or reset the route version.
  4. Recover orphaned margin locksOrders that locked margin but never produced an order row (broken event chain) are reaped by the lock-reconciler daily at 02:00 UTC; for an immediate release run perpctl lock-reconciler --from <RFC3339> --to <RFC3339> --dry-run, then without --dry-run. Stranded completion events are replayed per docs/2026-10-27-arb-order-event-replay-runbook.md.
  5. Revert config only from zero stateOnly after confirming zero positions, zero orders, zero triggers, zero unsettled funding and no external exposure may the market be disabled and removed from edge / market data subscriptions.
  6. Parameter changesIf Binance changes filters, funding or brackets during the rollout, freeze the affected markets, generate a new snapshot and a new config version, and OPEN again only after the diff is reviewed.

Final rule

When an A-book market fails, tighten admission and repair the A-book; never auto-degrade to B-book. Any operation that changes execution ownership is a separate migration task, not a rollback step of this runbook.
