首次上线 · A-book 直连 Binance

14 个永续市场发布 Runbook

本批市场均尚未对用户上线。它们在 PM Perp 中直接初始化为 A_BOOK，由 MM Connector 执行、Quote 镜像 Binance 行情。不存在 B-book 存量路由，因此不运行 marketctl book-switch，也不加入 Finex shard。

安全边界

数据库行可设为 status=active 以便各服务发现市场，但首次写入必须是 operational_state=FROZEN。完成行情、connector、Kafka、风险和账户检查后，再通过 Admin A-book state API 逐个改为 OPEN。

四条原则

执行归属execution_book=A_BOOK、desired_execution_book=A_BOOK。Finex 收到 MarketSync 后应忽略这些市场。
价格归属Mark、order book、trade tape、kline、ticker 均以 Binance USD-M 对应 symbol 为准；A-book Mark 的 Binance 权重为 1.0。
保证金模式A-book 仅允许 isolated。Cross-margin 下单必须被拒绝，默认市场设置需落为 isolated。
逐市场放量先 FROZEN 完成验证，再一次只 OPEN 一个市场；观察一个完整检查窗口后才进入下一市场。

禁止

不执行 book-switch；不把市场写入任何 Finex configured_markets；不复用旧文档中的通用风险档位；不把 OKX/Bybit 混合价用于 A-book 强平；不在没有 Binance leverage bracket 快照时开放。

必须从 Binance 对齐、但不在公共 exchangeInfo 中

max_allowed_leverage、首档 maintenance_margin_rate 以及完整 perps_market_risk_tiers，必须在发布当天用只读 Binance key 调用签名接口 GET /fapi/v1/leverageBracket。每个 bracket 的 notionalCap → max_position_qty、initialLeverage → max_leverage、maintMarginRatio → maintenance_margin_rate 原样导入；initial_margin_rate = 1 / initialLeverage。没有快照即停止发布。

NeoDAX 自有参数不要伪装成 Binance 参数

maker_fee_rate、taker_fee_rate、depth_level、mm_address、max_net_notional、超时和等待窗口按平台策略配置。max_net_notional 不得高于 Binance 第一档 notional cap，并受 connector 全局限额约束。market_order_margin_buffer 按平台 A-book 风险策略固定等于 Binance 首档 maintenance_margin_rate，以达到 Binance MMR 两倍的保护目标。

发布日参数快照与门禁

静态表仅用于审核。实际 seed 必须由发布日快照生成或逐项 diff；外部参数可能随时变化。

# 公共参数（保存原始响应、UTC 时间和 SHA-256）
curl -fsS 'https://fapi.binance.com/fapi/v1/exchangeInfo' -o exchangeInfo.json
curl -fsS 'https://fapi.binance.com/fapi/v1/fundingInfo'  -o fundingInfo.json
curl -fsS 'https://fapi.binance.com/fapi/v1/premiumIndex' -o premiumIndex.json
sha256sum exchangeInfo.json fundingInfo.json premiumIndex.json

# 风险档位（USER_DATA 签名接口；使用只读 key，响应不得提交到公开日志）
GET /fapi/v1/leverageBracket?symbol=<BINANCE_SYMBOL>&timestamp=<ms>&signature=<HMAC>

门禁

  • STOP任一 symbol 不是 TRADING，或 contract type 与预期不符。
  • STOPseed 的 tick / step / min / max / notional / percent-price / funding / interest / liquidation fee 与快照不一致。
  • STOP缺少任一 leverage bracket，或 tier 非连续，或 max_net_notional 超过允许上限。
  • STOPBinance 执行账户没有该 symbol 的交易权限、isolated 设置或足够保证金。
  • PASS14 个 symbol 的原始 JSON、抽取表、SHA-256 和审核人写入发布工单。

确保系统 House 账户已创建

A-book 共用的 House 账户必须同时存在于 PM Perp 数据库和 Raft FSM。固定 account_id 与 app_session_id 均为 00000000-0000-0000-0000-000000000009，owner 为零地址。此项未通过时禁止执行市场 seed 或开放市场。

4.1 检查 leader 启动日志

kubectl logs -n <namespace> <leader-pod-name> | grep "\[SYSTEM_ACCOUNTS\]"

正常

[SYSTEM_ACCOUNTS] account present in FSM and DB, no action needed
[SYSTEM_ACCOUNTS] all system accounts verified present in FSM

第一行是 Debug 日志；生产日志级别未开启 Debug 时，只看到最终的 all system accounts verified 也属于正常结果。

[SYSTEM_ACCOUNTS] account found in DB but missing from FSM, registering into FSM
[SYSTEM_ACCOUNTS] account registered into FSM successfully
[SYSTEM_ACCOUNTS] all system accounts verified present in FSM

[SYSTEM_ACCOUNTS] account found in FSM but missing from DB, back-filling database record
[SYSTEM_ACCOUNTS] database record back-filled successfully

异常（启动失败）

[SYSTEM_ACCOUNTS] CRITICAL: system account missing from FSM after reconciliation

出现该日志，或没有最终的 all system accounts verified present in FSM 时，立即停止发布，不得继续 seed 或 OPEN。

4.2 无停机修复系统账户

仅对当前 Raft leader 执行。该操作会对账全部必需系统账户（包括 A-book House），并按缺失方向补齐数据库或 FSM；可重复执行。

grpcurl -plaintext \
  -import-path . \
  -proto internal/protocol/proto/perp_pm.proto \
  -d '{
    "operation": "register_system_account",
    "operator": "ops",
    "reason": "bootstrap_system_account_fsm",
    "owner": "0x0000000000000000000000000000000000000000"
  }' \
  <leader-host>:50051 \
  portfolio.PerpPortfolioService/AdminAdjustFSM

成功响应

{
  "success": true,
  "message": "system accounts synchronized"
}

修复后门禁

重新执行 4.1 的日志检查，必须看到 all system accounts verified present in FSM。若响应为 not leader，重新定位 leader 后再执行；任何 success: false 均视为未修复。

回退与故障处置

出问题时先冻结、保留证据，再按 A-book 路径修复。回退动作不改变执行归属。

  1. 立即 FROZEN使用同一个 A-book state API，把目标市场改为 FROZEN；不要 book-switch 到 B-book。
  2. 保留证据记录 operation id、route version、connector offsets、订单与成交、外部账户快照、reconciliation diff、行情序列和告警时间线。
  3. 处理敞口有用户 / House / 外部仓位时保持 FROZEN，按 A-book cancel-all / reconcile / reconcile-order 路径修复。禁止直接删市场或重置 route version。
  4. 仅零状态可撤销配置确认零仓位、零订单、零 trigger、零未结资金费且外部账户无敞口后，才可停用市场并从 edge / 行情订阅移除。
  5. 参数变化若 Binance 在 rollout 中修改 filter、funding 或 bracket，冻结受影响市场，生成新快照与新 config version，完成 diff 审核后再 OPEN。

最终原则

A-book 市场故障时收紧准入并修复 A-book，不自动降级为 B-book。任何会改变执行归属的操作都属于另一项迁移任务，不是本 runbook 的回退动作。
