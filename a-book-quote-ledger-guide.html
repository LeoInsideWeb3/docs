任务的本质

A-Book 市场的成交发生在币安，内部 trades 会变得稀疏（只剩用户自己的成交）——用它们聚合 K 线就是假 K 线；同时内部订单簿不再存在。所以：quote 直接搬币安全量行情（深度 / K 线 / ticker / 成交带 / 过滤器），ledger 直接吃币安的 K 线。

下游（trading-api / PM Perp）零改动——因为事件格式和 topic 完全不变。这是整个任务的验收标准。

quote 服务：三层结构

quote 不碰用户数据、不写数据库，是纯流处理器。代码在 quote/，配置在 nacos configs/nacos/quote.yaml。

引擎层（quote/engine/）

engine.go 的 Engine 管理一组行情源并搭起计算流水线。所有行情源实现同一个 20 行的接口 provider.Source（quote/engine/provider/interface.go）：Subscribe(market) / Subscriptions() / Done()。加新数据源 = 实现这个接口。

Provider数据现状
binance_spot币安现货成交流现货价候选源
coinapi多所现货成交聚合现货价主源（付费）
binance_perp币安合约现在只订 markPrice 流，nacos 里只配了 btc/usdt、eth/usdt——这是你要扩展的
bitfaker合成数据测试用

两条处理路径（engine.go:201 的 switch，:309 分叉）

路径流向
trades 路径（现货）trades → router.go 按市场分 channel → 聚合器（100ms 窗口，按价格+方向合并）→ 指标（VWMA / momentum / moving_std，indicator/ 目录）→ outbox

发布层（quote/quotes_publisher.go）

QuotesService.Run 消费引擎 outbox，发 Kafka：trades 发现货价；mark price 发同一个 topic 但带 mark / index / funding 三个字段，市场名经 resolveSymbolPerp（:113）映射成 BTCUSDT-PERP（:254-262）。

mark 价体系（quote 里最复杂的部分，但有现成钩子）

internal_perp_trade 这个源

markoracle/internal_perp_trade_collector.go 把「内部成交」当价格源。A-Book 市场成交搬去币安后它就没有信息量了——任务之一是按市场停用它。

ledger 服务：纯消费者 + 读服务

ledger 只做两件事：把内部成交变成 K 线，把 K 线和 ticker 提供出去。代码在 ledger/，存储用 TimescaleDB（Postgres + 时序扩展）。

为什么这个任务不是「加个消费者直写」

K 线 100% 由内部 trades 聚合，高周期全部构建在 ohlc_1m 之上。A-Book 市场的成交在币安，内部 trades 稀疏，聚合出的 K 线没有代表性。但 spot 和 B-Book perp 市场仍然要走 trades 链。

所以是两条聚合链并存、按市场路由：perp A-Book 市场的聚合源改指向币安 K 线源表，spot / B-Book 市场的 trades 链原封不动。这是存储与聚合的重设计，不是加一个消费者。

三条铁律

① 格式不变

发出去的 topic 和事件格式必须和现在一模一样：orderbook 增量与 Finex 现有格式逐字段一致，EventQuoteObserved / EventTickerUpdated 不改结构。下游（trading-api / PM Perp / ledger 消费端）零改动是验收标准。

② 按市场门控，绝不全局切换

spot 和 B-Book perp 的路径语义一个字节都不能变。所有新逻辑挂在「A-Book 市场」的开关后面；设计文档第 6 页的 spot 边界矩阵是验收清单。

③ displayed = enforced

你发布的 mark 就是 PM Perp 强平用的 mark。A-Book 市场必须严格等于币安 mark——权重 100%，不许混合。否则会出现「用户看到价格没到强平价，却被强平了」。

前置条件

① quote 容器能出网访问 fapi.binance.com（REST 引导）与 fstream.binance.com（depth + kline 流）；② 本分支镜像已构建；③ Nacos 上 quote / ledger 配置已可写。

配置清单（逐字段）

三份配置缺一不可。下面是可以直接粘贴的完整片段，字段名与代码 yaml tag 一致。

# ── Nacos: quote ─────────────────────────────────────────────
engine:
  symbol_aliases_perp:            # 必须覆盖 A-Book 全部市场，否则 quote 启动失败
    BTCUSDT: "BTCUSDT-PERP"
  providers:
    binance_perp:
      orderbook:
        markets:                  # provider 格式 base/quote；空列表 = 关闭镜像
          - "btc/usdt"
        publish_depth: 50         # 发布档位数，对齐 Finex
        snapshot_interval: 1s     # 全量快照节奏
        rest_base_url: "https://fapi.binance.com"
      # klines_enabled 默认 true：与 depth 复用同一 worker 连接
      # exchangeinfo_poll_interval 默认 1h；显式写 0 关闭

# ── Nacos: ledger ────────────────────────────────────────────
ledger:
  markets:                        # gapfill 桶：A-Book 不要放进来
    - "eth/usdt"
  a_book_perp_markets:            # 内部符号；必须同时留在上面的 markets 里（24h ticker 要）
    - "BTCUSDT-PERP"
  external_klines:
    backfill_interval: 2m         # 水位巡检 + 缺口回补节奏
    backfill_lookback: 6h         # 缺口检测窗口；> 1000m 启动失败（币安单次上限）

# ── Nacos: finex（B-Book 实例）──────────────────────────────
configured_markets:               # 移除 A-Book 市场，否则与 quote 双写同一 topic
  - "eth/usdt"

三条硬失败规则（启动即退出，不静默降级）

① 缺 symbol alias → orderbook mirror market ... has no perp symbol alias；宁可起不来，也不要把盘口发到错误 topic。

② 非法 market 条目 → 同上，构造阶段直接拒绝。

③ backfill_lookback > 1000m → ledger 启动失败（不静默截断，避免误导性的「已补齐」）。

部署顺序（八步，顺序有理由）

#动作命令通过判据为什么必须在这个位置

四层联调验证

L1 事件流Kafka · 格式与序号

订阅 A-Book 盘口 topic，确认三件事：① 首条是 EventOrderbookSnapshot（不是增量）；② 增量与随后的快照共享同一 sequence，序号单调递增；③ 删除档位的 amount = "0"。

kafka-console-consumer.sh --bootstrap-server $KAFKA \
  --topic orderbook.BTCUSDT-PERP.OrderBookUpdates --from-beginning --max-messages 5

断链时不要指望自己补——quote 会重引导并补发快照，消费方只需按 sequence 重放。

L2 quote 指标Prometheus · 推进性与账目平衡

六个指标注册在现有 /metrics 端点，无需任何额外运维配置。核心是一条恒等式：received_total = stale_total + applied_total + 缺口重引导丢弃。

quote_orderbook_mirror_received_total{market="BTCUSDT-PERP"}
quote_orderbook_mirror_applied_total{market="BTCUSDT-PERP"}
quote_orderbook_mirror_stale_total{market="BTCUSDT-PERP"}
quote_orderbook_mirror_gap_rebootstraps_total{market="BTCUSDT-PERP"}
quote_orderbook_mirror_publish_errors_total{market="BTCUSDT-PERP",kind="snapshot|increment"}
quote_orderbook_mirror_last_bootstrap_unix_seconds{market="BTCUSDT-PERP"}
L3 ledger 落库TimescaleDB · 写入与读取

确认外部链有行、union 视图能查到该市场、最后一根未收线 bar 的 event_time 单调前进。

-- 外部链有数据？（未收盘的 bar 也在）
SELECT market, max(open_time) AS last_bar, max(event_time) AS watermark
FROM external_klines_1m WHERE market='BTCUSDT-PERP' GROUP BY market;

-- union 视图对前端可读
SELECT bucket, open, high, low, close, total FROM ohlc_1m_all
WHERE market='BTCUSDT-PERP' ORDER BY bucket DESC LIMIT 5;

-- 抽查 24h ticker 有覆盖
SELECT count(*) FROM ohlc_1m_all
WHERE market='BTCUSDT-PERP' AND bucket > now() - interval '24 hours';
L4 端到端trading-api · 客户端视角

trading-api 零改动：盘口走 orderbook.{MKT}.OrderBookUpdates（与 B-Book 同 topic 同格式），K 线与 ticker 走 ledger gRPC 读 ohlc_{{interval}}_all。只要市场进了 enabled_futures_markets，Centrifuge 订阅即刻有数据。

wsctl  # 或前端：订阅 BTCUSDT-PERP 的 orderbook + kline 频道
判据：盘口 100ms 级刷新、无跳空；K 线与币安官网同一根 bar 的 OHLC 完全一致

回滚

1quote 关市场

把 orderbook.markets 置空 → 停镜像与 K 线流，进程保持健康。

2finex 恢复

若步骤 7 已执行，把市场加回 B-Book configured_markets（前提是币安侧已无持仓/挂单）。

3ledger 可不动

a_book_perp_markets 留着无害：外部链历史数据保留，切回 B-Book 后 union 自动只出 B 侧数据。

回滚前提

A-Book 与 B-Book 的订单/持仓在币安真实账户上，切换必须零持仓、零挂单（含 perp_trigger 等待单）——这正是任务 1 的 marketctl 要断言的四件事。在它落地前，切换只能人工核对。
