  5. Immediately rolling-restart finex-perp-1/2/3Each instance loads its new configured_markets + order books. Must happen before quote — otherwise once quote produces prices, orders get accepted by PM but never matched (stuck orders). Commands on page 6.
  6. Restart quoteMark prices for the new markets start flowing (the mark price gate passes). From this moment the full order path works. Verify mark freshness (page 9, item 4).
  7. Restart ledgerK-line aggregation starts consuming the new markets' trades.
  8. Smoke verificationWork through the 7 items on page 9 + small open/close round trips on 2-3 representative markets.

Restart order iron rule: finex → quote → ledger (trading-api needs no restart)

Getting this wrong opens a "orders accepted by PM but nobody matching" stuck-order window. Each service's hot-reload behavior dictates the order:

ServiceConfigBehaviorRequirement

10 · Rollback

When Something Goes Wrong

Ordered from smallest to largest blast radius. If config-only rollback suffices, don't touch the database.

Roll back a single market

-- 1. Remove the market from trading-api's enabled_futures_markets, restart trading-api
-- 2. Remove it from the quote configs, restart quote
-- 3. Set inactive in the DB (existing data unaffected):
UPDATE portfolio_manager_perp.perps_markets
SET status = 'inactive', updated_at = NOW()
WHERE symbol = '<MKT>USDT-PERP';

Full rollback

-- 1. trading-api: remove all new markets from enabled_futures_markets, restart
-- 2. quote: remove the new symbol_aliases / mark_oracle / binance_perp entries, restart
-- 3. ledger: remove the new perp_markets entries, restart
-- 4. finex: restore the original configured_markets, restart
-- 5. DB: set all inactive
UPDATE portfolio_manager_perp.perps_markets
SET status = 'inactive', updated_at = NOW()
WHERE symbol IN (
  'XAUUSDT-PERP','XAGUSDT-PERP','CLUSDT-PERP',
  'ARBUSDT-PERP','UNIUSDT-PERP','NEARUSDT-PERP',
  'ADAUSDT-PERP','AAVEUSDT-PERP',
  'NVDAUSDT-PERP','CRCLUSDT-PERP','MSTRUSDT-PERP',
  'TSLAUSDT-PERP','GOOGLUSDT-PERP','1000PEPEUSDT-PERP'
);

Do not delete DB rows or Kafka topics

Existing trades, positions, and audit records reference these markets. Setting inactive is enough — deleting rows breaks the history chain. Keep the Kafka topics; they cost nothing.

SAFE_MODE handling

If a market enters SAFE_MODE (all mark price sources down), opens are rejected but closes/cancels still work. See docs/2026-08-28-delist-perp-mark-price-runbook.md for handling leftover mark price holds.
