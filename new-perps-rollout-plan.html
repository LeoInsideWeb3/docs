热加载行为矩阵（防操作员失误的关键）

trading-api：enabled_futures_markets 热加载（Nacos 一变即生效，无需重启）——这是第 4 步暴露市场的原因。PM Perp：市场表 60s 自动 reload（seeds 后无需重启；重启也可）。finex：configured_markets 只在启动时读取——必须重启。quote：mark oracle 权重等可热调，但新 symbol 的 WS 订阅必须重启。ledger：markets 列表启动时读取——必须重启。重启顺序铁律：finex → quote → ledger（trading-api 不用重启）。

min_sources = 1 永久锁定

任何市场、任何时候都不要把 mark_price_min_sources_normal 改成 2 或 3。多源强制会把市场推进 SAFE_MODE（历史事故：开单被全拒）。行情源可以多接（Binance/OKX/Bybit 三家都接上，权重分散），但 min_sources 判定线永远是 1——只要还有一个源活着就正常。

出问题怎么办

按影响范围从小到大排列。能只回配置就不动数据库。

只回某个市场

-- 1. 从 trading-api 的 enabled_futures_markets 移除该市场,重启 trading-api
-- 2. 从 quote 的相关配置移除,重启 quote
-- 3. DB 置 inactive(不影响已有数据):
UPDATE portfolio_manager_perp.perps_markets
SET status = 'inactive', updated_at = NOW()
WHERE symbol = '<MKT>USDT-PERP';

全部回滚

-- 1. trading-api: 从 enabled_futures_markets 移除全部新市场,重启
-- 2. quote: 移除新增 symbol_aliases / mark_oracle / binance_perp 条目,重启
-- 3. ledger: 移除新增 perp_markets 条目,重启
-- 4. finex: 恢复原来的 configured_markets,重启(注意 finex-3 恢复为原来的重复配置)
-- 5. DB: 全部置 inactive
UPDATE portfolio_manager_perp.perps_markets
SET status = 'inactive', updated_at = NOW()
WHERE symbol IN (
  'XAUUSDT-PERP','XAGUSDT-PERP','CLUSDT-PERP',
  'ARBUSDT-PERP','UNIUSDT-PERP','NEARUSDT-PERP',
  'ADAUSDT-PERP','AAVEUSDT-PERP',
  'NVDAUSDT-PERP','CRCLUSDT-PERP','MSTRUSDT-PERP',
  'TSLAUSDT-PERP','GOOGLUSDT-PERP','1000PEPEUSDT-PERP'
);

不要删 DB 行和 Kafka Topic

已有成交、持仓、审计数据关联这些市场。置 inactive 即可，直接删会断历史链。Kafka topic 保留，不影响成本。

SAFE_MODE 处理

如果某个市场进入 SAFE_MODE（mark price 全断），开仓会被拒但平仓/撤单仍可用。参见 docs/2026-08-28-delist-perp-mark-price-runbook.md 处理 mark price hold 残留。
